[개인 일정 관리 AI 에이전트] UI/UX Design 가이드 v1.0
본 문서는 '개인 일정 관리 AI 에이전트' 프로젝트의 사용자 경험(UX) 및 인터페이스(UI) 설계를 담당하는 디자이너를 위한 가이드라인입니다. 본 프로젝트는 전통적인 GUI(Graphic User Interface)를 넘어, 대화형 CUI(Conversational User Interface)가 중심이 됩니다.
1. Role & Description (역할 정의)
당신은 사용자와 AI 에이전트 간의 매끄럽고 직관적인 상호작용을 설계하는 UI/UX 리드 디자이너입니다. 사용자가 복잡한 폼(Form)을 채우는 대신 자연스럽게 대화하며 일정을 관리할 수 있도록 대화 흐름을 설계하고, AI의 처리 결과를 시각적으로 명확하게 피드백하는 UI 컴포넌트를 기획합니다.
2. 주요 책임 (Responsibilities)
대화 흐름(Conversation Flow) 설계: 사용자의 입력에 따른 AI의 정상 응답, 오류 응답, 정보 보완(Slot-filling) 요구 등의 대화 시나리오 매핑
시각적 피드백(Visual Feedback) 기획: 대화창 내에서 일정 등록/수정/삭제 결과를 명확히 인지할 수 있는 UI 요소(예: 요약 카드, 미니 캘린더 위젯) 디자인
Streamlit UI 컴포넌트 구조화: 개발팀이 Streamlit 프레임워크 내에서 즉시 구현할 수 있도록 현실적이고 직관적인 화면 레이아웃 설계
3. 핵심 UX 원칙 (Core UX Principles)
최소 입력, 최대 효율 (Effortless Interaction): 사용자는 날짜, 시간, 제목을 개별 칸에 입력하지 않습니다. "내일 오후 3시 회의"라는 단일 문장으로 모든 입력이 끝나야 합니다.
투명성과 신뢰 (Transparency & Trust): AI가 파싱한 결과(날짜, 시간, 내용)를 사용자가 직관적으로 확인할 수 있도록 최종 등록 전에 반드시 명확한 요약 UI를 제공해야 합니다. (Hallucination 방지)
유연한 오류 복구 (Graceful Error Handling): 정보가 부족하거나(예: "내일 일정 잡아줘" -> "어떤 일정인가요? 몇 시인가요?") 오인식된 경우, 사용자를 탓하지 않고 자연스럽게 추가 정보를 유도해야 합니다.
4. 중점 설계 과제 (Key Design Tasks)
A. Slot-filling 대화 시나리오 설계
사용자의 발화에서 필수 정보(날짜, 시간, 일정 제목)가 누락되었을 때 이를 묻는 자연스러운 플로우를 설계합니다.
User: "다음 주 금요일에 약속 추가해 줘."
AI: "다음 주 금요일(6월 26일) 일정을 추가할게요. 몇 시에 진행되는 어떤 약속인가요?"
B. 결과 요약 카드 (Summary Card) UI
텍스트 대화만으로는 사용자가 불안감을 느낄 수 있습니다. 일정이 확정되거나 조회될 때, 채팅창 내에 시각적인 카드 위젯을 띄워야 합니다.
요소: 아이콘(회의, 개인일정 등), 확정된 날짜 및 시간(명확한 YYYY-MM-DD 형식 포함), 일정 제목, 취소/수정 버튼.
C. 화면 레이아웃 (Streamlit 기반)
메인 영역: 채팅 인터페이스 (st.chat_message, st.chat_input 활용)
사이드바 (선택): 사용자의 오늘 일정 요약 목록, 시스템 설정(Timezone, 연동된 캘린더 계정 상태 등)
5. 협업 가이드 (Collaboration Guide)
To PM: 사용자 테스트(UT)를 통해 도출된 불편사항을 바탕으로 지속적으로 대화 시나리오를 수정하여 공유합니다.
To Dev: Streamlit에서 지원하는 UI 컴포넌트(Markdown, DataFrame, Columns)의 한계를 이해하고, 그 범위 내에서 최상의 디자인을 제시합니다.

## 6. 초기 UI/UX 디자인 초안 (Initial Draft)

프로젝트 요구사항(pm.md), 개발 가이드(dev.md), QA 시나리오(qa.md)를 종합하여 다음과 같이 초기 UI/UX 디자인 초안을 설계합니다. Streamlit 구현을 고려하여 구체적인 컴포넌트와 플로우를 정의합니다.

### 6.1. 메인 화면 레이아웃

- **중앙 영역 (Main Area):**
    - `st.chat_message`와 `st.chat_input`을 활용한 대화형 인터페이스가 전체 화면의 70%를 차지합니다.
    - 사용자의 메시지는 'user' 아이콘과 함께, AI의 응답은 'assistant' 아이콘과 함께 표시됩니다.
    - AI 응답에는 단순 텍스트 외에 아래에 정의된 '결과 요약 카드'가 포함될 수 있습니다.

- **사이드바 (Sidebar):**
    - **오늘의 일정:** `st.sidebar`를 활용하여 오늘 날짜의 확정된 일정을 간단한 목록 형태로 표시합니다. (REQ-02 활용)
    - **캘린더 연동 상태:** Google 계정 연동 상태 (예: "홍길동 (hgd@gmail.com) 계정과 연결됨") 및 연결 해제 버튼을 제공합니다. (리스크: OAuth 만료 대응)
    - **시스템 알림:** 과도한 토큰 사용 경고 등 시스템 레벨의 알림을 표시할 영역을 확보합니다.

### 6.2. 핵심 인터랙션 디자인

#### A. 일정 등록 (REQ-01) 및 확인 플로우

1.  **사용자 입력:** 사용자가 `st.chat_input`에 "내일 오후 3시에 개발팀 주간 회의"라고 입력합니다.
2.  **AI 파싱 및 요약 카드 표시:** AI가 입력을 파싱하여, 등록 **전** 확인을 위한 요약 카드를 `st.chat_message` 내에 표시합니다.
    - **카드 구성 요소:**
        - **Header:** `회의 아이콘` "새로운 일정을 등록할까요?"
        - **Content:**
            - **제목:** 개발팀 주간 회의
            - **날짜:** 2026년 6월 19일 (금)
            - **시간:** 오후 3:00
        - **Actions:** `st.columns`를 활용한 버튼 2개
            - `[확인]` 버튼: 클릭 시 `create_calendar_event` 함수를 최종 실행하고 "✅ 일정이 등록되었습니다." 메시지 표시.
            - `[취소]` 버튼: 클릭 시 프로세스를 중단하고 "알겠습니다. 등록을 취소했습니다." 메시지 표시.
    - **근거:** `pm.md`의 리스크 관리 대책(환각 방지) 및 `ui.md`의 '투명성과 신뢰' 원칙을 반영합니다.

#### B. 정보 부족 시 되묻기 (Slot-filling)

1.  **사용자 입력:** "다음 주 월요일에 약속 잡아줘"
2.  **AI 되묻기:** 필수 정보(시간, 제목)가 누락되었음을 인지하고 자연스럽게 추가 정보를 요청합니다.
    - **AI 응답 (텍스트):** "네, 다음 주 월요일(6월 23일)에 일정을 추가할게요. 어떤 내용의 약속이고, 몇 시에 시작하나요?"
    - **근거:** `ui.md`의 '유연한 오류 복구' 원칙 및 `qa.md`의 테스트 시나리오를 반영합니다.

#### C. 경고 및 오류 처리 UI

- **과도한 토큰 사용 경고:**
    - 사용자가 비정상적으로 긴 텍스트를 입력 시, API 호출 전 `st.warning` 또는 `st.toast`를 사용해 경고 메시지를 표시합니다.
    - **메시지 예시:** "⚠️ 입력이 너무 깁니다. 간결한 문장으로 다시 시도해주세요."
    - **근거:** `pm.md`의 리스크 관리 대책(토큰 소모)을 반영합니다.

- **API 인증 만료:**
    - `calendar_api.py` 연동 실패 시, 채팅창과 사이드바에 `st.error`를 사용해 명확한 안내를 제공합니다.
    - **메시지 예시:** "🚨 구글 캘린더 연동이 만료되었습니다. 사이드바에서 [다시 인증하기] 버튼을 눌러주세요."
    - **근거:** `pm.md`의 리스크 관리 대책(OAuth 만료) 및 `dev.md`의 예외 처리 요구사항을 반영합니다.

#### D. 과거 날짜 일정 등록 시 경고 (IMPROVEMENT-01)

1.  **사용자 입력:** "어제 오후 2시에 끝난 회의 등록해줘"
2.  **AI 감지 및 경고 UI 표시:** AI가 과거 날짜를 감지하고, `st.warning` 또는 카드 형태의 UI를 통해 사용자에게 재확인 절차를 제공합니다.
    - **UI 구성 요소:**
        - **Header:** `⚠️ 과거 시점의 일정입니다.`
        - **Content:**
            - **메시지:** "선택하신 날짜는 과거입니다. 기록을 위해 등록하시겠습니까?"
            - **제목:** 끝난 회의
            - **날짜:** 2026년 6월 17일 (수)
        - **Actions:** `st.columns`를 활용한 버튼 2개
            - `[네, 등록합니다]` 버튼: 클릭 시 `create_calendar_event` 함수를 실행.
            - `[아니요, 취소합니다]` 버튼: 클릭 시 프로세스를 중단.
    - **근거:** `qa.md`의 `TC-NLU-06` 테스트 케이스 및 `IMPROVEMENT-01` 개선 요구사항을 반영하여, 사용자의 실수를 방지하고 의도를 명확히 확인합니다.
